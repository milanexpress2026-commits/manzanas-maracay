## Ejecuciones y límites

- `npm run check` pasó con 286 pruebas unitarias, comprobación de tipos y builds de API/web. El primer intento tuvo un timeout de un subproceso de prueba de seguridad; el caso dirigido pasó sin cambiar límites y la repetición completa pasó.
- La suite completa ejecutó 115 casos: 106 aprobados y 9 fallidos. Las recuperaciones dirigidas posteriores validaron los 9 restantes. Hay 115 casos distintos aprobados entre ejecuciones; no se presenta esto como una ejecución única de 115 casos aprobados.
- Se corrigieron únicamente expectativas de pruebas reemplazadas por V4.5: etiquetas de Binance, resumen de recepción sin costos y conservación del residuo de costo de los tres blísteres por su contenedor de origen. No cambió el código evaluado ni el esquema.
- Las conexiones nuevas de PostgreSQL en Windows excedieron 3 segundos bajo ráfagas. El ensayo con API en Windows y PostgreSQL en Linux añadió latencia de red por consulta: una venta respondió 201 en 9,5 segundos, antes de que terminara la navegación posterior. Se conserva esa evidencia; no se elevaron timeouts ni se ocultaron fallos. Los tres casos restantes pasaron con aplicación, navegador y base juntos en Linux aislado, del 6 de noviembre a las 21:12:45–21:14:03 UTC, sobre el mismo código `817a278`.
- El primer ensayo de producción aprobó el cierre de rutas públicas y detectó una expectativa antigua de siete pasos de preparación; V4.5 usa tres. Se corrigieron las dos aserciones para comprobar títulos, destinos y estado pendiente/registrado, conservando la apertura cerrada y las comprobaciones comerciales. No se modificó la aplicación.
- La repetición completa de producción aislada pasó 13/13 casos, del 6 de noviembre de 2026 a las 21:55:41.114–21:58:18.557 UTC: dos de acceso/base vacía, uno del recorrido inicial, cuatro de interfaz y seis de API. Se verificaron 21 tablas comerciales vacías al inicio, propietario de migración limitado, limpieza de la base temporal y parada de PostgreSQL. Los seis archivos de pruebas superpuestos se verificaron antes y después; el runtime siguió siendo `817a278`.
- El vídeo continuo del recorrido vacío fue generado durante esa ejecución aprobada. Su importación e inspección visual siguen pendientes; no se presenta como vídeo revisado todavía.
- Las pruebas comerciales de QA no demuestran que se hayan registrado transacciones reales en el negocio.

## Compatibilidad que se conserva

- Recepciones anteriores con costos explícitos y sus claves idempotentes siguen legibles y reproducibles. Las pruebas nuevas no reinterpretan esos costos como cero.
- Las aserciones históricas de costo se contrastan en la base aislada; la API operativa, la interfaz y los PDF ya no deben revelar costos ni utilidades.
- Los casos que exigían costo o lista para una operación nueva se adaptan a la regla V4.5, conservando sus verificaciones de inventario, auditoría, concurrencia y recuperación.
- Los registros de precio históricos permanecen sin cambios; una venta manual no crea ni actualiza listas.

## Límites de la evidencia

Las capturas y el vídeo representan Chromium con tamaños de pantalla emulados. No prueban una tablet física, un teclado Android real ni una prueba con personas ajenas al desarrollo. Esas verificaciones se indicarán como pendientes mientras no existan evidencias. La URL real y el estado del VPS se documentarán por separado después del proceso autorizado de publicación.
